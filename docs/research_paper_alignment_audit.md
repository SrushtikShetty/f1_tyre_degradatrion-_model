# Research-Paper / Repository Alignment Audit

**Audit date:** 17 October 2026  
**Inspected main revision:** 38bdff2fc8c3adbfb4e420eeb7ff7a82ef17d33d  
**Working branch:** research/aggression-paper-audit

## Executive finding

The current active training path supports a **synthetic F1-style tyre-degradation benchmark**, not a measured real-telemetry study. The corrected trainer uses race states generated in-repository and a next-lap response emitted by an authored degradation function. The driver-aggression rating is generated by the simulator; it is not inferred from observed throttle, brake, speed, gear, RPM, or coordinates. FastF1 ingestion is not active in the corrected trainer. The authoritative explainability report uses grouped permutation importance and declares that SHAP was not computed.

The revised manuscript is therefore an evidence-aligned synthetic-benchmark study and protocol for a future real-telemetry experiment. It reports the existing synthetic metrics while preserving the real-aggression hypothesis as untested. It does not reuse historical near-perfect scores from the legacy deterministic target as evidence of physical tyre prediction.

## Data lineage and target validity

### Legacy tables

- train.csv has 233,640 rows; test.csv has 12,916 rows.
- The legacy wear labels match W(a,c)=min(100, r_c(a-1)), where r_HARD=1.0, r_MEDIUM=1.5, and r_SOFT=2.5.
- The next-lap difference is consequently recoverable from compound and tyre age until the cap/boundary behaviour.
- The audit reports an exact lookup by compound-age with holdout R²=1.0 and MAE=0.0 on the legacy target. This indicates target determinism, not physical predictive validity.

### Semi-synthetic derived tables

- data/derived/original_derived_seed_42_part1.csv and part2.csv derive from the legacy source tables.
- src/f1_tyre/original_derived_benchmark.py builds the target using an authored current-state formula and seeded variation.
- A more complex synthetic equation does not convert source rows into independent measurements.

### Current authoritative synthetic benchmark

- Generator: data_generation/generate_dataset.py.
- Target response: src/f1_tyre/synthetic_degradation.py.
- Configuration: data_generation/config.json.
- Generation seed: 20261004.
- Generated state rows: 34,560; modelling rows: 33,840; races: 60; drivers per race: 12; laps per driver sequence: 48.
- Recorded CSV SHA-256: c9121cdc3f5d00b7ba9e65c3af6bda27a038a9eb2ce6f241f0b94f6af483127a.
- The generator holds each driver's compound fixed through the generated sequence; realistic pit-stop tyre-set resets are not represented.
- The synthetic label includes a generated aggression rating, so model accuracy cannot validate a real telemetry-derived aggression construct.

| Baseline | R² | MAE | RMSE |
|---|---:|---:|---:|

| Compound only | 0.5382431 | 0.1676746 | 0.2152461 |

On this synthetic holdout, XGBoost MAE is approximately 36.9% lower than the compound-age lookup baseline. This statement is scoped strictly to the synthetic generator and is not a real-race performance claim.

The authoritative validation grouped-permutation results report increase in MAE of 0.230583 for tyre state, 0.108574 for fuel/energy, and 0.029570 for the combined driver/team group. That last group combines generated aggression, skill, consistency, and team inputs; the result does not isolate the effect of aggression.

## Changes made on the audit branch

1. **Canonical dashboard metrics:** backend/app.py now reads the versioned final evaluation report and exposes final-holdout R², MAE, and RMSE with explicit benchmark scope.
2. **Canonical explainability endpoint:** the API now exposes grouped permutation values from the authoritative report, including available variability fields. Its response says that these are validation-MAE increases, not local attributions or causal effects, and explicitly notes that SHAP was not computed.
3. **Regression tests:** tests/test_api.py now checks final-holdout metric extraction, synthetic dataset scope, the grouped permutation method, and non-SHAP wording.
4. **README accuracy:** the README now documents the corrected registry, Git LFS requirement, canonical evaluation path, CPU XGBoost configuration, and current synthetic-only scope.
5. **IEEE manuscript:** The companion deliverable paper.tex is the canonical editable source, with embedded bibliography and editable TikZ/PGFPlots figures. The source and compiled PDF are provided as files for this review; the manuscript was not committed into this branch. There is no separate refs.bib file required.
6. **Audit report:** this document records source-to-paper status, metric provenance, known gaps, and validation outcomes.

## Remaining limitations

- The final metrics artefact records training revision b82b2a3c4c22215be0797ad6d3f710688757ba9c, which predates the audited main head 38bdff2fc8c3adbfb4e420eeb7ff7a82ef17d33d. Later commits are refactors, but a current-head rerun was not completed in this environment.
- The authoritative generated CSV is not tracked. Regenerate it and verify its SHA-256 before attempting exact result reproduction.
- The complete repository pytest suite was not run in this runtime. A shallow Git clone failed because github.com DNS resolution was unavailable. The new API test contract exists, but its runtime result is not confirmed here.
- Authentic FastF1 session loading, telemetry-derived intensity, fuel/pace target validation, raw-versus-composite aggression ablation, race-cluster bootstrap intervals, leave-circuit-out evaluation, and SHAP remain unimplemented or unrun.
- The source-provenance and physical-validity gaps cannot be resolved by code-only changes without authentic measurements or a validated external degradation estimator.
